# EduPlatform

EduPlatform — навчальна вебплатформа для керування курсами, навчальними матеріалами, тестуванням студентів та відстеженням навчального прогресу.

Проєкт розроблено як курсову роботу з дисципліни «Веб-технології та веб-дизайн».

## 1. Технології та вимоги

- ASP.NET Core MVC (.NET 10)
- Entity Framework Core
- SQLite
- Playwright для наскрізного тестування
- xUnit для модульного та інтеграційного тестування

Для запуску потрібні .NET SDK 10, операційна система Windows та веббраузер. Для E2E-тестування додатково потрібні Node.js і npm.

## 2. Отримання, збирання та запуск

Усі команди цього розділу виконуються в терміналі Windows із кореневого каталогу репозиторію, де розташований файл `EduPlatform.slnx`.

Отримати вихідний код можна шляхом клонування репозиторію або завантаження архіву релізу `v1.0.0`.

Виконати команди:

```powershell
dotnet restore EduPlatform.slnx
dotnet build EduPlatform.slnx
dotnet run --project EduPlatform/EduPlatform.csproj --launch-profile http
```

Після запуску відкрити у браузері:

http://localhost:5225

Під час першого запуску база даних SQLite створюється автоматично методом `EnsureCreated()`. Початкові демонстраційні дані ініціалізуються засобами застосунку.

Для зупинки сервера натиснути `Ctrl+C` у терміналі.

## 3. Інструкція користувача

Система підтримує три категорії користувачів:

- **Гість:** перегляд публічного каталогу курсів, реєстрація та вхід.
- **Студент:** приєднання до курсів, перегляд матеріалів, проходження тестів, перегляд результатів і прогресу.
- **Викладач:** створення та редагування власних курсів, навчальних матеріалів і тестових питань, перегляд результатів студентів своїх курсів.

Для початку роботи потрібно відкрити головну сторінку, зареєструватися або увійти до облікового запису, після чого вибрати доступну дію відповідно до ролі.

Під час проходження тесту студент надає відповіді на питання. Система перевіряє допустимість спроби, автоматично оцінює відповіді та зберігає результат. Якщо ліміт спроб вичерпано або введено некоректні дані, операція відхиляється з відповідним повідомленням.

Для завершення роботи необхідно вийти з облікового запису.

## 4. Конфігурація та база даних

Основні налаштування зберігаються у файлі `EduPlatform/appsettings.json`.

Параметр підключення до SQLite:

`ConnectionStrings:DefaultConnection`

Значення за замовчуванням:

`Data Source=eduplatform.db`

Параметри локального запуску визначені у файлі `EduPlatform/Properties/launchSettings.json`.

Для звичайного запуску застосунку використовується `EnsureCreated()`. Файли міграцій Entity Framework Core зберігаються в каталозі `EduPlatform/Migrations/` і використовуються в окремих сценаріях перевірки схеми бази даних. Не слід застосовувати міграції до робочої бази, створеної через `EnsureCreated()`, без попередньої перевірки сумісності та резервного копіювання.

Робоча база даних, локальні секрети, тимчасові файли та користувацькі завантаження не включаються до Git-репозиторію.

## 5. Інструкція адміністратора

Адміністрування локального середовища включає налаштування конфігурації, перевірку журналів застосунку, контроль стану SQLite та оновлення програмного коду.

Журнали запуску й помилок можна переглядати в терміналі, у якому працює ASP.NET Core.

Тестового користувача можна створити через інтерфейс реєстрації. Права користувача визначаються реалізованими механізмами автентифікації та авторизації.

Для резервного копіювання необхідно завершити роботу застосунку та створити копію файлу SQLite разом із потрібними супровідними файлами бази даних, якщо вони існують.

Для відновлення потрібно зупинити застосунок, зберегти поточний стан бази, відновити резервну копію та перевірити запуск системи.

**Увага:** заміна або видалення робочої бази даних може призвести до втрати курсів, облікових записів і результатів тестування. Перед такими операціями обов’язково створюється резервна копія.

## 6. Програмні інтерфейси

EduPlatform використовує ASP.NET Core MVC і HTTP-запити GET та POST для взаємодії користувача із системою.

Основні операції включають перегляд каталогу й деталей курсів, авторизацію, приєднання до навчання, проходження тестів, перегляд результатів і керування навчальними матеріалами.

Доступ до захищених операцій визначається роллю користувача та належністю відповідного об’єкта. У разі неавторизованого доступу, відсутності ресурсу або некоректних даних система повертає відповідну відмову чи повідомлення про помилку.

Окремий публічний REST API у межах проєкту не реалізовано. Архітектуру інтерфейсів і контрактів описано в підрозділі 3.8 пояснювальної записки.

## 7. Тестування

### Модульні та інтеграційні тести

Із кореневого каталогу репозиторію Windows:

```powershell
dotnet test EduPlatform.slnx
```

### E2E-тести Playwright

У терміналі Windows перейти до каталогу `e2e-tests` та виконати:

```powershell
npm ci
npx playwright install chromium
```

В іншому терміналі запустити EduPlatform за інструкцією розділу 2.

Після цього в каталозі `e2e-tests` виконати:

```powershell
npx playwright test
```

Для окремих тестів авторизації необхідно локально встановити змінні середовища з обліковими даними тестових користувачів. Паролі та інші секрети не можна зберігати в репозиторії.

За результатами перевірок, описаних у курсовій роботі, успішно виконано 92 наскрізні тести Playwright, 10 тестів xUnit та 10 додаткових перевірок адаптивності, доступності й браузерної сумісності.

Протоколи функціонального, навантажувального тестування, аналізу продуктивності та експериментів із SQLite наведено в розділі 5 пояснювальної записки.

## 8. Структура проєкту

- `EduPlatform/` — вихідний код вебзастосунку.
- `EduPlatform/Migrations/` — міграції Entity Framework Core.
- `e2e-tests/` — наскрізні тести Playwright.
- `EduPlatform.slnx` — файл рішення .NET.
- `README.md` — інструкції з використання, запуску та перевірки.
- `.gitignore` — правила виключення службових і конфіденційних файлів.

## 9. Обмеження

EduPlatform призначена для навчального використання та локальної демонстрації. Система не включає платіжні механізми, відеоконференції, зовнішні сервіси автентифікації та окремий мобільний застосунок.

Автоматизовані перевірки підтверджують працездатність досліджених сценаріїв, але не охоплюють усіх можливих умов промислової експлуатації. Відомі обмеження продуктивності, тестового покриття, безпеки та відмовостійкості наведено в розділі 5 курсової роботи.
